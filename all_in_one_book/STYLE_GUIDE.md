# 写作与术语规范（STYLE GUIDE）

本书的写作纪律。每次提交前都要拿这份对照自查。违反任何一条都视为不合格。

---

## 1. 声音与腔调

- **对象**：一个聪明、但完全没用过 Symfony、甚至框架经验不深的 PHP 开发者。
- **人称**：用"你"，不用"我们"；必要时用"作者"（作者本人）。
- **口吻**：像一个耐心的老同事在工位旁边讲给你听，不像教科书。
- **句子长度**：平均 25 汉字以内。一句话说不清的，拆成两句。

## 2. 翻译腔零容忍

> "翻译腔 = 读起来能一眼看出是从英文逐词译过来的。"

- ❌ "我们需要去做……的事情" → ✅ "你要……"
- ❌ "这允许你能够……" → ✅ "这样你就能……"
- ❌ "一个路由的定义可以被放置在……" → ✅ "路由可以写在……"
- ❌ "众所周知 / 显而易见 / 不言自明 / 理所当然" → **全部删除**。若读者觉得"显而易见"他就不会读你这本书。

## 3. 术语一致性

- 以 `GLOSSARY.md` 为唯一真源。
- 写作时遇到新术语 → **先去 GLOSSARY 查** → 查不到就补一条再继续写。
- 第一次出现保留英文原词（括号内），后续用选定的中文译法或直接保留英文：
  - ✅ 首现："**依赖注入容器**（Dependency Injection Container，简称 DI 容器）"
  - ✅ 后续："DI 容器" 或 "容器"
- 不允许同一概念在不同章节用不同译法。

## 4. 禁用词

以下词语在正文中**严禁使用**（除非在反讽/引用场景并加引号）：

- "显然、不言自明、自然地、理所当然、众所周知、简单地、轻而易举、不用多说、一目了然、so easy"
- "相信读者自己能……"（除非是"留作练习"的练习题末尾）
- "此处略、详见官方文档、TODO、待补充、FIXME、以后再讲"

## 5. 代码样例

- 所有 PHP 代码以 `<?php` 开头（除非是 Twig / YAML / XML）
- 每个文件第一行用注释标文件路径：
  ```php
  // src/Controller/BookController.php
  ```
- Symfony 8 / PHP 8.4+ 的写法（官方 `setup.rst` 最低要求）：
  - 构造器属性提升（constructor property promotion）
  - readonly 属性
  - `#[Route]` 等属性（Attribute），**不再写 annotation `@Route`**
- YAML 配置必须带文件路径注释、缩进 4 空格、value 不加多余引号
- 每段示例都必须是**可直接 copy-paste 进项目运行**的。只粘一个片段就跑不起来的，必须在上下文补齐（或链到本章前面已给出的完整文件）。

## 6. 命令行

- 统一用 `$ ` 开头表示 shell 提示符
- 默认用 `php bin/console xxx`，如果 Symfony CLI 更方便则写 `symfony console xxx` 并解释一次。
- 长命令断行用反斜杠续行，保持 80 字符/行以内
- 输出示例用 **缩进 4 空格**（不用代码块嵌套）或单独 `text` 代码块

## 7. 图示

- 首选 **ASCII 图**（Markdown 里直接可见、不依赖渲染）
- 复杂时序图可用 Mermaid（` ```mermaid `）
- 每张图必须有**图题**（图下方一行斜体）
- 图中出现的每一个方块，正文必须有对应解释

## 8. 目录与文件命名

- 目录用编号前缀：`00_getting_started/`、`02_routing/`
- 文件同样用编号前缀，中文名用下划线连接：`01_心智模型.md`
- 小节编号从 01 起，留出 99 给速查表
- 所有内部链接用**相对路径**：`../09_service_container/04_配置项逐项讲解.md#自动装配`

## 9. 每一节固定结构（强制）

每一节 Markdown 顶部必须有这个元信息块：

```markdown
# 章节标题

> **一句话说明**：……
> **对应官方英文文档**：`<path>.rst`（仓库根相对路径）
> **Symfony 版本基准**：8.0
> **前置阅读**：……
```

然后按任务书第 5 节的 14 个段落展开。不适用的段落写上"**本节无此项，原因是 ……**"，不可直接省略。

## 10. 三道质量闸门（每节写完自查）

### 闸门一：新手压力测试

假想一个"刚学完 PHP 基础、没碰过任何框架"的人读你这一节，他会问：

- 这个类我要放哪里？
- autowire 到底自动做了啥？
- 为什么我改了配置没生效？
- 这个服务 ID 是哪来的？

**你的文本必须已经答过这些问题**。否则回去改。

### 闸门二：自我代码审查

- 所有代码在 Symfony 8.0 / PHP 8.4+ 环境下能 copy-paste 运行？
- 配置片段里每一行我都解释过了？
- 有没有"此处略"？
- 读起来像不像一个中国人自己写的？
- 术语跟 GLOSSARY.md 一致？

### 闸门三：差异化检查

- 这一节相比官方英文文档，**至少多讲了 3 样东西**（选择指南 / 报错图鉴 / 调试 / 反模式 / 源码 / bookstore / FAQ / 图解 中的任意 3 项）？
- 没有就等于没写，回去重写。

## 11. 提交规范

- commit 消息前缀：
  - `docs(book): 新增 NN_xxx/NN_标题.md`
  - `docs(book): 完善 NN_xxx/NN_标题.md 的 XX 部分`
  - `chore(book): 更新 PROGRESS.md`
- 一节一提交（鼓励小步）
- 每次会话最后一次提交**一定是** `chore(book): 更新 PROGRESS.md`

## 12. 交叉引用

- 引用其它章节用相对链接：`见 [09.DI 自动装配](../09_service_container/04_配置项逐项讲解.md#autowire)`
- 引用官方 `.rst` 原文用仓库根相对路径：``见 `routing.rst` 第 X 节``
- 引用 Symfony 源码用 `vendor/symfony/<component>/<File>.php` 的形式，并给出关键行号（源码行号会随版本漂移，标注"在 Symfony 8.0.x 里约第 XXX 行")

## 13. 数字、单位、标点

- 中英文之间加空格："Symfony 8.0 的 Container"
- 中文里用**中文标点**："，。：；！？"
- 代码、路径、命令、文件名左右加空格："修改 `services.yaml` 后"
- 枚举用全角的"、"或半角的 ","，一篇内不混用

---

**宁可一次只交付一节高质量内容，也绝不提交十节半成品。**
